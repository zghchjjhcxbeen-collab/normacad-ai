## 1. Что сделано в ЭТОЙ сессии (2026-06-11)

### 1.1. Слой обоснования по базе ГОСТ (ядро продуктового видения владельца)
Под каждым замечанием — **реальная цитата пункта из базы ГОСТ** (не выдуманная) + «сверить с PDF».
- `app/gostdb.py` → `grounding_quote(number, anchors)`: тянет формулировку пункта по якорю, склейка OCR-переносов, `lru_cache`. **Анти-галлюцинация: нет якоря → `None`, цитата не выдумывается.**
- `app/ruleset.py` → у каждого правила `ground_anchors` (фразы из чистой прозы стандарта).
- `app/templates/_job_fragment.html` → блок «Что говорит ГОСТ»; стиль в `app/static/app.css`.
- `scripts/check_grounding.py` → сверка: все правила имеют цитату из базы.
- **Инвариант (критично!):** измеримые ЧИСЛА (высоты, форматы, масштабы, толщины) — только из `ruleset.py` (сверены руками по тексту/PDF). LLM/OCR числа НЕ поставляют — OCR-таблицы шумные.

### 1.2. Вектор-PDF — Этап 4, первый срез
Born-digital PDF идёт **тем же движком и обоснованием**, что DXF.
- `app/parsing/pdf.py` (НОВЫЙ): PDF → тот же `ParsedDrawing`. Формат — из размеров страницы (MediaBox→мм). Масштаб — из текста штампа, с валидатором `_looks_like_scale` (одна сторона = 1, обе ≤ 1000 — отсекает даты/номера типа `2024:01`). Скан (нет текстового слоя) → `source_format="raster_pdf"` + «загрузите вектор-PDF/DXF». Многостраничный → предупреждение «проверена 1-я стр.».
- `app/parsing/dispatch.py` (НОВЫЙ): `parse_drawing(path)` — маршрут по расширению (ленивые импорты).
- `app/rules/engine.py`: `run_checks` ветвится по `source_format`. **DXF — без изменений**; `vector_pdf` = надёжно 2.301+2.302, а 2.304/2.104 → INFO «ручная проверка» (точность важнее охвата: метрики шрифта и таблицу штампа на PDF надёжно не реконструировать).
- Загрузка принимает `.pdf` (`app/config.py`); воркер пишет `Drawing.format_class`.
- `scripts/make_bootstrap_pdf.py` (НОВЫЙ, fpdf2). Зависимости: **pdfplumber, fpdf2** (+pypdfium2 транзитивно — пригодится на растровом тракте Этапа 5).

### 1.3. Качество ядра (закрыты реальные источники ложных срабатываний)
- **Детект формата (грабли №6 закрыты):** `_largest_rectangle_mm` берёт наибольший замкнутый контур (рамку), а не общий bbox. `clean_a3` теперь точно **420×297**; текст за рамкой габарит не раздувает. Нет полилинии → fallback на bbox с предупреждением.
- **Детект штампа:** `_has_title_graphs` — распознаём штамп и по содержимому (графы наимен./обозн./масштаб), не только по имени блока → меньше ложного critical «штамп не обнаружен» на чужих DXF.
- Адверсариальные тесты (`tests/test_dxf_parsing.py`).

### 1.4. Правило 2.303 (толщина линий) — готово
- `app/parsing/dxf.py` → `_collect_lineweights_mm` (явные lineweight, BYLAYER→слой).
- `app/rules/checks.py` → `check_lines_2303`: основная линия **0,5–1,4 мм** (сверено с п.5 базы). **Молчит, если толщины не заданы явно** (часто задаются стилем печати) — без ложняков.
- Обоснование из базы: «Толщина сплошной основной линии s… от 0,5 до 1,4 мм».

### 1.5. Безопасность (Этап 1) — НАЧАТА
- `app/services/uploads.py` (НОВЫЙ): **проверка содержимого по сигнатуре (magic bytes)** (`.exe`→`.dxf` и PDF-как-DXF отклоняются) + **санитизация имени** (`../../`, слэши, опасные символы). Подключено в `/uploads`.
- **Осталось:** CSRF на формах, rate-limit на `/login`/`/uploads`, Alembic вместо `create_all`, `secure=True` для cookie в проде.

## 2. Ключевые РЕШЕНИЯ этой сессии (зафиксировать)

1. **Приватность бэкенда (владелец):** облако Claude — **только для обычных пользователей**; конструкторские бюро и предприятия — **только локально**. → Бэкенд чата/vision выбирается **по типу пользователя/организации** (поле у `User`), не глобально. Для bureau/enterprise облачный путь должен быть недоступен в принципе.

2. **СКОУП — что проверяем и что принципиально НЕТ** (важный разговор, не потерять):
   - **ДА — правильность ОФОРМЛЕНИЯ (нормоконтроль):** соответствие ЕСКД (формат, масштаб, шрифты, линии, штамп, обозначения…). База ГОСТ нужна именно для этого — сослаться на пункт.
   - **НЕТ — правильность КОНСТРУКЦИИ:** «не та шестерня», «узел не работает», «допуск не под функцию» — это инженерная валидность, **её нет ни в одном ГОСТе** (нужны замысел/функция/расчёты). База ГОСТ = справочник ПРАВИЛ оформления, а НЕ база «правильных конструкций».
   - Это совпадает с PLAN: «предварительный фильтр, а не замена нормоконтролёра»; в НЕ-целях — достаточность видов/замкнутость цепей/соответствие функции не обещаем.
   - Максимум «умного» по дорожной карте (vision-слой, **ассистивно, с пометкой «требует проверки человеком»**): непротиворечивость документа (пропущенные виды 2.305, порядок ТТ 2.316, сноски 2.109), условные изображения — но это всё про КОРРЕКТНОСТЬ ДОКУМЕНТА, не про валидность инженерного решения.
   - **Открытое предложение владельцу:** добавить в отчёт и на сайт явный блок «что проверяем / что на совести конструктора».

3. **Precision-first:** правило лучше промолчит (или отдаст в «ручную проверку»), чем выдаст ложное замечание. Доверие нормоконтролёра рушится от первой ошибки.

## 5. Грабли (не повторять)

- Starlette: `templates.TemplateResponse(request, "name.html", {ctx})` — request первым.
- Консоль Windows = cp1251: в скриптах `sys.stdout.reconfigure(encoding="utf-8")` + запуск с `$env:PYTHONUTF8='1'`.
- Не удалять `normacad.db`, пока запущен сервер (Windows держит файл) → сначала `taskkill /f /im python.exe`.
- Glob по пути с кириллицей (`БАЗА`) не работает — прямой `Read` по известным путям.
- Числа — только из `ruleset.py`; тексты ГОСТ целиком в облако не слить (копирайт), только короткие выдержки.
- bcrypt напрямую (пароль ≤72 байт); без JWT (серверные сессии); без сторонних CSS-фреймворков.
