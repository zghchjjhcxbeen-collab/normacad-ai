# DWG — технический spike и решение go/no-go

> Контекст: PLAN.md, Этап 7 («DWG за лицензионным гейтом») и Этап −1 (spike DWG).
> Вопрос: можем ли мы принимать `.dwg` напрямую и с каким качеством/риском.
> Дата: 2026-06-11. Статус: **NO-GO для MVP/демо; условный GO для Phase 2 (on-prem)**.

---

## 1. Суть проблемы

- `ezdxf` (наш парсер вектора) **не читает DWG** — только DXF. Это подтверждено документацией библиотеки.
- DWG — закрытый бинарный формат Autodesk. Чтобы его разобрать, нужен сторонний конвертер
  DWG→DXF либо отдельная библиотека. У всех вариантов есть проблема: **лицензия, стабильность
  или приватность** — а у нас есть режимный сегмент, где облако недопустимо.

---

## 2. Обзор вариантов конвертации DWG→DXF

| Вариант | Лицензия | Где работает | Надёжность | Пригодность |
|---|---|---|---|---|
| **ODA File Converter** (Open Design Alliance) | бесплатно скачать, но коммерческое/SaaS-встраивание требует членства ODA | локально (GUI+CLI) | высокая, все версии DWG | **только on-prem**, не для нашего SaaS |
| **LibreDWG** (`dwg2dxf`, python-libredwg) | GNU GPL/LGPL | Linux нативно; Windows — сборка через MSYS2/vcpkg | средняя; на сложных DWG из AutoCAD 2018+ возможны потери | кандидат для on-prem, нужен тест на реальных файлах |
| **Aspose.CAD for Python** | коммерческая, платная (триал с ограничениями) | локально (через .NET/Java-рантайм) | высокая | вариант, если есть бюджет; on-prem |
| **Teigha/ODA SDK** | коммерческая | локально | высокая | дорого, избыточно для MVP |
| **CloudConvert / Zamzar / Autodesk APS** | облачные API, платно | облако | высокая | **ЗАПРЕЩЕНО**: КД уходит в чужое облако — нарушает приватность |

Ключевые ограничения:
- **SaaS-путь упирается в лицензии.** Бесплатный ODA нельзя встроить в наш облачный сервис;
  LibreDWG свободен, но рискован по надёжности; Aspose — деньги.
- **Облачные конвертеры исключены** для режимного сегмента (и вообще нежелательны — это
  ровно тот канал утечки, от которого мы защищаемся `resolve_backend`).

---

## 3. Потери при конвертации (почему даже успешный DWG→DXF — не бесплатно)

Из spike-гипотез PLAN.md (Этап −1) и природы формата:
- **Ассоциативные размеры (DIMENSION)** могут «взрываться» в линии+текст — тогда `get_measurement`
  не работает, и геометрические проверки 2.307/2.309 теряют опору (они и так за гейтом).
- **Блоки/ATTRIB штампа** при конвертации иногда сохраняются неполно → детект штампа 2.104
  деградирует (но у нас уже есть fallback по подписям граф — грабли №9).
- **Слоевая семантика** (контур/ось/размеры по слоям) может не пережить round-trip.

Вывод: конвертация добавляет **второй источник ошибок** поверх собственно проверок. Для
precision-first продукта это прямой риск ложных замечаний на ровном месте.

---

## 4. Решение

### MVP / демо — NO-GO (не поддерживаем DWG напрямую)
Причины: лицензии (SaaS), риск надёжности (LibreDWG), приватность (облако исключено),
потери объектов. Выгода низкая: **все целевые CAD (AutoCAD, КОМПАС, nanoCAD, SolidWorks)
экспортируют DXF и вектор-PDF в пару кликов** — это и так наши поддерживаемые форматы.

**Реализовано (этот спайк):** честная деградация вместо общего отказа. При загрузке `.dwg`/`.dwf`
пользователь получает конкретную подсказку «экспортируйте в DXF или вектор-PDF из вашего CAD»
(`app/services/uploads.py: unsupported_ext_message`, подключено в `/uploads`, покрыто тестом).

### Phase 2 / on-prem (секретный контур) — условный GO
Когда клиент разворачивает сервис у себя:
- **ODA File Converter, установленный самим клиентом** на его машине, вызывается нашим кодом как
  subprocess в песочнице с таймаутом. Лицензия — клиента; данные не покидают периметр.
  Это снимает и лицензионный, и приватностный барьеры. **Требует подтверждения условий ODA.**
- Альтернатива — LibreDWG, если устроит надёжность (проверить на реальных файлах).
- Интеграция тривиальна: DWG→DXF в temp, дальше существующий DXF-тракт без изменений.

### Что блокирует настоящий quality-спайк
Нужны **реальные DWG целевых предприятий** (10–20 файлов разных CAD/версий), чтобы измерить:
долю успешных конвертаций, сохранность DIMENSION/штампа/слоёв, число ложных замечаний после
round-trip. Без них оценка — кабинетная. Это тот же блокер, что и для корпуса (трек A).

---

## 5. Краткий ответ владельцу

DWG в MVP не берём — это лицензионно/технически дорого и не нужно: любой CAD отдаёт DXF/PDF.
Сейчас на загрузку DWG сервис честно отвечает «экспортируйте в DXF или вектор-PDF». Когда дойдём
до on-prem-поставки для предприятия, добавим конвертацию через установленный у клиента ODA
(данные не уходят наружу) — но сначала нужны их реальные DWG, чтобы померить потери.
