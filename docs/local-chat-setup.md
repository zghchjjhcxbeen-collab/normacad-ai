# Локальная модель ИИ-чата (Ollama) — установка и подключение

> Для кого: конструкторские бюро и предприятия, чьи данные не должны покидать периметр.
> Облачный Claude для них запрещён на уровне кода (`app/chat.py: resolve_backend`) —
> чат работает либо на **локальной модели**, либо на офлайн-справочнике по базе ГОСТ.
> Эта инструкция поднимает локальную модель на той же машине, где крутится сервис.

Весь обмен с моделью идёт по локальному адресу `127.0.0.1` и наружу не уходит.
В модель передаются только короткие выдержки из ГОСТ (не целые тексты), как и в облачном режиме.

---

## 0. Требования к железу

- ОС: Windows 10/11 (инструкция под неё; Ollama есть и под Linux/macOS).
- Видеопамять (ориентир для квантованных Q4-моделей):
  - **6–8 ГБ** → модель 7B (рекомендуется по умолчанию);
  - **12 ГБ (например, RTX 4070)** → 7B с запасом или 14B;
  - меньше 6 ГБ / без дискретной GPU → пойдёт на CPU, но ответы будут медленными.
- Свободно на диске: ~5 ГБ на модель 7B, ~9 ГБ на 14B.

Целевая машина из плана (RTX 4070, 12 ГБ) тянет `qwen2.5:7b` свободно и `qwen2.5:14b` с запасом.

---

## 1. Установить Ollama

1. Скачать установщик: https://ollama.com/download/windows (файл `OllamaSetup.exe`).
2. Запустить, пройти установку. После неё Ollama стартует как фоновая служба и слушает
   `http://127.0.0.1:11434` (порт по умолчанию). Перезагрузка не требуется.
3. Проверить, что служба жива — в PowerShell:
   ```powershell
   ollama list
   ```
   Команда должна отработать без ошибки (список моделей пока пуст — это нормально).

---

## 2. Загрузить русскоязычную модель

По умолчанию рекомендуется **Qwen2.5** — сильная многоязычная модель с хорошим русским.

```powershell
ollama pull qwen2.5:7b      # ~4,7 ГБ, безопасный выбор для 8–12 ГБ VRAM
# или, если есть 12 ГБ и нужно качество получше:
# ollama pull qwen2.5:14b   # ~9 ГБ
```

Быстрый тест прямо из консоли (без нашего сервиса):
```powershell
ollama run qwen2.5:7b "Назови минимальную высоту шрифта на чертеже по ГОСТ 2.304"
```
Первый запуск грузит модель в видеопамять — он медленнее последующих.

> Альтернативы Qwen2.5, если захотите сравнить: `gemma2:9b`, `llama3.1:8b`.
> Узкоспециализированные русские модели (Saiga и т.п.) тоже подключаются, но требуют
> ручной сборки из GGUF через Modelfile — это отдельный сценарий, для старта не нужен.

## 3. Настроить сервис на локальную модель

В корне проекта (`C:\Users\elisei\OneDrive\Desktop\8776`):

1. Если файла `.env` ещё нет — скопировать из примера:
   ```powershell
   Copy-Item .env.example .env
   ```
2. Открыть `.env` и задать три значения (имя модели — ровно как в `ollama list`):
   ```ini
   CHAT_BACKEND=local
   LOCAL_CHAT_URL=http://127.0.0.1:11434/v1
   LOCAL_CHAT_MODEL=qwen2.5:7b
   ```

Что это значит:
- `CHAT_BACKEND=local` — локальная модель включается для **всех** пользователей.
- Бюро и предприятия пойдут в локальную модель **в любом случае** (даже если глобально
  стоял бы `claude`) — это жёстко зашито в коде ради приватности.

---

## 4. Проверить связь (диагностический скрипт)

```powershell
$env:PYTHONUTF8 = '1'
.\.venv\Scripts\python.exe scripts\check_local_chat.py
```

Скрипт проверит: отвечает ли endpoint, загружена ли указанная модель, и задаст реальный
вопрос по ГОСТ тем же кодом, что и веб-чат. При успехе в конце будет
`ГОТОВО. Локальная модель подключена и отвечает.`

Если что-то не так — скрипт подскажет причину (служба не запущена, не та модель, не тот порт).

---

## 5. Проверить в веб-чате

```powershell
$env:PYTHONUTF8 = '1'
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Открыть http://127.0.0.1:8000, войти, перейти в **Чат**, задать вопрос по ГОСТ.
Под полем ответа бэкенд будет `local`. Для пользователя с типом «бюро»/«предприятие»
это гарантировано — облако им недоступно.

## 6. Диагностика проблем

| Симптом | Причина | Что делать |
|---|---|---|
| `Сервер модели НЕ отвечает (соединение отклонено)` | Ollama не запущена | `ollama list`; если ошибка — переустановить/запустить Ollama |
| HTTP 404 при генерации | Модель не загружена | `ollama pull qwen2.5:7b`; сверить `LOCAL_CHAT_MODEL` с `ollama list` |
| Ответ очень долгий (десятки секунд) | Первый запрос грузит модель в VRAM, либо модель идёт на CPU | подождать прогрева; убедиться, что GPU задействована (`nvidia-smi`) |
| Чат отвечает офлайн-справочником, а не моделью | `CHAT_BACKEND` не `local` или пустой `LOCAL_CHAT_URL` | проверить `.env`, перезапустить сервер |
| Ответ невнятный/путаный | Слабая/маленькая модель | взять `qwen2.5:14b` вместо `7b` |

---

## 7. Важные замечания

- **Конфликт портов.** Наш сервис по умолчанию слушает порт **8000**. Не используйте для
  локальной модели тоже 8000 (в `.env.example` так показан только vLLM-вариант). С Ollama
  конфликта нет — у неё **11434**.
- **`.env` не коммитить** — там настройки конкретной машины.
- **Перезапуск.** После правки `.env` сервис нужно перезапустить — настройки читаются на старте.
- **Числа считает не модель.** Проверка чертежей (форматы, высоты, масштабы, штамп) —
  детерминированный код, без ИИ. Локальная модель отвечает только в чате-справочнике и
  опирается на выдержки из базы ГОСТ. Точные числовые требования всё равно сверяются по тексту
  стандарта.
