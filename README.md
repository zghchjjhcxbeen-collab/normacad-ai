# NormaCAD AI

**B2B-сервис предварительного ИИ-нормоконтроля инженерных чертежей по ГОСТ/ЕСКД.**
Загружаешь чертёж (DXF / вектор-PDF) → сервис проверяет оформление по ЕСКД → отчёт со списком
замечаний, каждое привязано к месту на чертеже, к пункту ГОСТ и снабжено рекомендацией «как исправить».
Цель — **сократить число возвратов** документации от нормоконтроля к конструктору.

Полный план и архитектура — в [PLAN.md](PLAN.md). Сценарий показа — в [docs/demo-script.md](docs/demo-script.md).

> **Главный принцип:** измеримые факты (формат, высоты, масштаб, толщины) считает
> **детерминированный код, а не языковая модель** — ИИ не имеет права выдумывать числа.
> Это предварительный фильтр, **не замена нормоконтролёра** (ГОСТ 2.111).

## Что работает (проверено тестами — 52 зелёных)

**Ядро проверок (детерминированное, офлайн)** — `app/rules/`, `app/parsing/`:
- ГОСТ **2.301** — формат листа (A4…A0); **2.302** — масштаб из ряда; **2.304** — высота шрифта;
  **2.303** — толщина линий; **2.104** — наличие/заполненность основной надписи.
- Форматы: **DXF** (ezdxf) и **born-digital вектор-PDF** (pdfplumber; 2.304 по cap-height).
- Откалибровано на реальном КОМПАС-экспорте (рамка/текст в блоках, штамп без ATTRIB).
- Версионируемый справочник констант ЕСКД (`app/ruleset.py`), не «магические числа».

**Веб-приложение** (FastAPI + Jinja2 + htmx, SSR):
- Загрузка, фоновая обработка, **отчёт с рендером реального чертежа и подсветкой замечаний на листе**.
- **Обратная связь нормоконтролёра**: триаж замечаний ИИ (подтвердить/ложное) + добавление
  пропущенных ИИ замечаний — сбор данных о точности.
- **Справочник ЕСКД** (`app/gostdb.py`): под замечанием — живая цитата пункта из базы ГОСТ.
- **ИИ-чат-справочник** по ГОСТ (мультичаты, история): бэкенд подключаемый.
- Современный интерфейс: app-shell, сайдбар, светлая/тёмная темы.

**Приватность (решение под режимных клиентов):** бэкенд чата выбирается **по типу пользователя** —
облако (Claude) допустимо только для обычных пользователей; **бюро/предприятия — только локальная
модель** (Ollama/llama.cpp/vLLM) или офлайн-справочник. Облако им недоступно на уровне кода
(`app/chat.py: resolve_backend`). Установка локальной модели — [docs/local-chat-setup.md](docs/local-chat-setup.md).

**Безопасность (Этап 1):** CSRF (double-submit cookie), rate-limit, magic-bytes + санитизация имён,
secure-cookie, Alembic-миграции.

**Инструменты:**
- `scripts/calibrate_corpus.py` — прогон папки чертежей через движок (per-file отчёт + сводка).
- `scripts/make_demo_files.py` — выверенный демо-набор (чистый + «грязный» с заложенными ошибками).
- `scripts/upload_to_site.py` — быстро залить файлы в кабинет запущенного сайта.
- `scripts/check_local_chat.py` — диагностика связи с локальной моделью.

## Запуск (Windows, без Docker)

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

# тест-данные + проверки
.\.venv\Scripts\python.exe scripts\make_bootstrap_dxf.py
.\.venv\Scripts\python.exe scripts\make_demo_files.py
$env:PYTHONUTF8 = '1'
.\.venv\Scripts\python.exe -m pytest -q          # 52 теста

# сайт
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Открыть http://127.0.0.1:8000. Демо-вход: **smoke@test.local / password123**.
Либо зарегистрироваться и загрузить `data/demo/demo_dirty.dxf` (поймает все правила) и
`data/demo/demo_clean.dxf` (0 замечаний).

## Структура

```
app/
  domain.py            доменные объекты (Finding, ParsedDrawing) — без инфраструктуры
  ruleset.py           версионируемый справочник констант + якоря обоснования ЕСКД
  gostdb.py            база ГОСТ: поиск + цитата пункта (обоснование, RAG)
  chat.py              ИИ-чат (resolve_backend: приватность по типу пользователя)
  parsing/             парсеры DXF / вектор-PDF + диспетчер по формату
  rules/               движок правил (ветвление по формату) + проверки P0
  routers/web.py       SSR-роуты: auth, загрузка, отчёт, обратная связь НК, чат
  services/            security, sessions, csrf, ratelimit, uploads
  svgview.py           рендер чертежа (ezdxf SVG / растр PDF) + подсветка
  templates/, static/  htmx-шаблоны + CSS (светлая/тёмная темы)
scripts/               генерация тест-данных, калибровка, демо, диагностика
docs/                  demo-script, local-chat-setup, dwg-spike
data/bootstrap/, data/demo/   синтетические DXF/PDF
alembic/               миграции
tests/                 pytest (52)
PLAN.md                полный план проекта (источник истины)
```

## Важные заметки для запуска

- **База ГОСТ — вне репозитория** (данные пользователя). Ядро проверок чертежей работает **без неё**;
  цитаты ГОСТ под замечаниями и чат-справочник требуют путь `GOST_DB_DIR` (см. `.env.example`).
- Настройки — через переменные окружения (`.env.example` → `.env`). У всех есть dev-дефолт.
- План B (dev): SQLite + обработка в процессе, без Docker. Прод — PostgreSQL + ARQ/Redis (см. PLAN.md).
