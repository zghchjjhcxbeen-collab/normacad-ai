## 1. Что сделано в ЭТОЙ сессии (2026-06-11, сессия 4)

### 1.1. Точность PDF 2.304 — CapHeight из дескриптора шрифта
- `app/parsing/pdf.py`: `_embedded_cap_ratios(path)` читает `/FontDescriptor /CapHeight` встроенных шрифтов 1-й страницы (pdfminer.six) → точный cap-ratio = CapHeight/1000 именно для этого шрифта.
- Приоритет в `_cap_ratio(fontname, embedded)`: **дескриптор → таблица `_CAP_RATIOS` → ненадёжный fallback**. Больше PDF дают `font_metrics_reliable=True` → 2.304 проверяется автоматически, меньше уходит в «ручную».
- Тесты в `tests/test_pdf.py`: портируемый (приоритет дескриптора над таблицей) + интеграционный на реальном встроенном TTF (`C:\Windows\Fonts\arial.ttf`, со скипом если нет).

### 1.2. PDF картинкой — растровый рендер листа с подсветкой
- `app/svgview.py`: `render_pdf_raster_svg(path, parsed, findings)` — pypdfium2 рендерит страницу в PNG (data-URI внутри `<svg><image>`), рамки замечаний — SVG-`<rect>` в пиксельных координатах. Совмещение: mm→px через `parsed.frame_size_mm`, переворот оси Y (в мм снизу-вверх, в растре сверху-вниз: верх = H−(y+h)). `_PDF_RENDER_DPI=150`.
- `render_drawing_svg` — диспетчер: DXF→ezdxf, vector_pdf/raster_pdf→растр (с деградацией на схему).
- `_severity_str(f)` — severity у ORM-Finding строка, у доменного enum → нормализация.
- Тест `tests/test_render.py` + ручная сверка координат (формат=весь лист, масштаб=зона штампа, шрифт=по месту).

### 1.3. Чат по типу пользователя (приватность)
- `app/models.py`: `User.org_type` (individual|bureau|enterprise, default individual).
- `app/chat.py`: **`resolve_backend(org_type)`** — единственная точка инварианта: бюро/предприятие + облачный бэкенд → принудительно local/stub. Облако (claude) им не отдаётся НИКОГДА. `_answer_local` — OpenAI-совместимый endpoint (LOCAL_CHAT_URL). `_build_messages` (DRY для claude/local).
- `app/config.py`: `local_chat_url`, `local_chat_model`.
- UI: селектор типа при регистрации (`register.html`), баннер «локальная обработка» в чате.
- `tests/test_chat.py` — маршрутизация + **тест-«ловушка»** (если код полезет в облако для бюро — падает).

### 1.4. Полный редизайн сайта (по референсу владельца)
- Референс — скрины Artem-версии (SaaS-сайдбар, оранжевый акцент, light/dark). Воспроизведено в Jinja2/htmx, **без CSS-фреймворков, иконки SVG (не эмодзи)**.

- `app/templates/base.html` — app-shell (сайдбар: лого, «Новый чат», навигация с иконками, «Проекты», профиль внизу с выходом; топбар: заголовок + переключатель темы + действие). `auth_base.html` — центрированная карточка для входа/регистрации.

## 5. Ключевые решения и факты-разъяснения (в силе)

1. **Проверка чертежей НЕ использует ИИ** — это детерминированный код (ezdxf/pdfplumber + `ruleset.py`). Намеренно: точность, офлайн, без галлюцинаций. ИИ только в чате (опционально) и в будущем растровом тракте (сканы, Этап 5–6).
2. **Продукт НЕ зависит от Claude.** Claude в этой работе = инструмент разработки (ассистент), не рантайм продукта. Бэкенд чата подключаемый: офлайн (stub) / облако Claude (только individual) / локальная модель (все типы). Для бюро/предприятий облако запрещено и это зашито в `resolve_backend`.
3. **Локальная связка для предприятий:** чат-LLM (Ollama/llama.cpp/vLLM + Qwen2.5/Saiga) + будущие VLM (зрение) и OCR (PaddleOCR ru) — всё на их сервере (RTX 4070, 12 ГБ → модели 7–14B Q4). Вместо Claude.
4. **Приватность бэкенда** по типу пользователя/организации, не глобально.
5. **СКОУП:** проверяем ОФОРМЛЕНИЕ (ЕСКД), не правильность КОНСТРУКЦИИ.
6. **Precision-first:** правило лучше промолчит/уйдёт в «ручную», чем выдаст ложное замечание.
7. **Первая демонстрация = первая реальная валидация;** метрики до пилота предварительны (синтетика + 1 реальный КОМПАС-файл — не корпус).
