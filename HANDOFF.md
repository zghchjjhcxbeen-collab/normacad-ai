## 1. Что это за проект

**NormaCAD AI** — сервис, который принимает чертёж (PDF, DXF, DWG, PNG, JPG), проверяет его на соответствие ЕСКД/ГОСТ и возвращает отчёт: список замечаний, каждое привязано к месту на чертеже, к пункту ГОСТ и сопровождается рекомендацией «как исправить». Цель — **сократить число возвратов** документации от нормоконтроля к конструктору, отсеяв грубые формальные ошибки.

**Позиционирование (важно):** мы — **предварительный фильтр, а не замена нормоконтролёра** (ср. ГОСТ 2.111). В отчёте градация «ошибка / предупреждение / рекомендация». Главный технический моат: **измеримые факты (высоты, форматы, масштабы) считает детерминированный код, а не LLM** — LLM не имеет права выдумывать числа.

Владелец проекта — пользователь (elisei). Идея выросла из проекта знакомого (Artem), но это самостоятельная реализация.

## 2. Ключевые решения (подтверждены владельцем)

| Тема | Решение |
|---|---|
| Цель | MVP / прототип |
| ИИ-ядро | **Гибрид**: детерминированный парсинг вектора (ezdxf/PDF) + Claude vision для растра/семантики |
| Форматы | **Все** (PDF/DXF/DWG/PNG/JPG): приём всех; но **высокая точность в MVP только для офлайн-парсимых** (DXF, вектор-PDF). Сканы/картинки/DWG — best-effort через vision |
| Стек | Пересмотрен: **FastAPI + SQLAlchemy(async)**; фронт **SSR на Jinja2 + htmx + Alpine** (без SPA/сборки); серверные сессии в cookie (**без JWT**) |
| Приватность | **Есть режимные/секретные клиенты** → ИИ-ядро **offline-способно с 1-го дня**; vision = **подключаемый бэкенд** (облако Claude для гражданки / локальная модель для секретного контура / выкл.). Для секретного сегмента — вероятно **on-prem поставка** (Phase 2) |
| Данные для калибровки | **Реального корпуса чертежей и эксперта-НК сейчас НЕТ** → калибруем на синтетике + тексте ГОСТ, метрики до пилота **предварительны**; первая демонстрация предприятию = первая реальная валидация (их штатный нормоконтролёр проверяет ИИ) |
| Вывод результата | Основной канал — **размеченный чертёж + цитата ГОСТ**; Excel-ведомость — опционально, под конкретное бюро |
| «Как исправить» | Каждое замечание содержит **конкретную рекомендацию** по исправлению |
| ИИ-чат | На сайте есть **чат-справочник по ГОСТ** (RAG над базой), бэкенд подключаемый |

**Развилка прод vs dev:** прод-цель — PostgreSQL + ARQ/Redis + Docker (на сервере владельца с RTX 4070). Сейчас выбран **План B (dev)**: **SQLite + обработка в процессе (BackgroundTasks)**, без Docker/Redis — потому что Docker на машине не установлен и ноут слабый. Слой обработки (`app/jobs.py`) написан так, что переключение на ARQ не трогает бизнес-логику.

## 3. Текущее состояние кода (Этап 0 — работает)

**Ядро движка (чистый Python, без инфраструктуры):**
- `app/parsing/dxf.py` — парсер DXF на ezdxf: единицы (`$INSUNITS`→мм), габарит рамки (bbox), тексты (TEXT/MTEXT с высотой в мм), основная надпись (INSERT-блок штампа + графы ATTRIB).
- `app/rules/checks.py` — 4 детерминированные проверки P0, каждая выдаёт `Finding` с локатором (handle/bbox) и рекомендацией `fix`:
  - **ГОСТ 2.301** — формат листа (A4…A0, допуск 5 мм);
  - **ГОСТ 2.302** — масштаб из ряда (графа 6 штампа);
  - **ГОСТ 2.304** — высота шрифта из ряда (мин. 2,5 мм);
  - **ГОСТ 2.104** — наличие штампа + заполненность обязательных граф (наименование/обозначение/масштаб).
- `app/rules/engine.py` — прогон всех правил + сводка.
- `app/ruleset.py` — **версионируемый конфиг констант ЕСКД** (`RULESET_VERSION="eskd-2024.0-bootstrap"`): форматы, ряды масштабов и высот, обязательные графы. Числа сверены с текстом ГОСТ (ряд высот 2.304 сверён с базой ✓).
- `app/domain.py` — доменные объекты `Finding` (с полем `fix`), `ParsedDrawing`, `TextItem`, `TitleBlock`, enum `Severity`/`Source`.

**Веб-слой (FastAPI, План B — SQLite):**
- `app/main.py` — точка входа, lifespan создаёт таблицы (`create_all`), монтирует статику, `/api/health`, `/api/docs`.
- `app/config.py` — настройки из env (см. раздел 8).
- `app/db.py` — async-движок SQLAlchemy + сессии (`sqlite+aiosqlite`).
- `app/models.py` — `User`, `AuthSession`, `Drawing`, `CheckJob`, `Finding`, `Report`, `ChatMessage`.
- `app/services/security.py` — bcrypt напрямую (усечение до 72 байт), валидация email регуляркой.
- `app/services/sessions.py` — серверные сессии в БД (cookie `ncad_sid` = opaque-токен).
- `app/jobs.py` — `process_job` (parse→rules→сохранить Finding+Report), `enqueue` через BackgroundTasks (точка подмены на ARQ).
- `app/svgview.py` — SVG-просмотрщик: `render_real_dxf_svg` рисует РЕАЛЬНЫЙ чертёж (ezdxf SVG backend, белая «бумага») с подсветкой ошибок прямо на листе (вписаны как сущности до рендера → точное совмещение); `render_schematic_svg` — запасная схема (PDF / при сбое рендера); `render_drawing_svg` — диспетчер.
- `app/routers/web.py` — все роуты (см. раздел 4).
- `app/templates/` — `base.html`, `login.html`, `register.html`, `dashboard.html`, `job.html`, `_job_fragment.html` (поллинг htmx + отчёт), `chat.html`, `_chat_messages.html`.
- `app/static/app.css` — тёмная тема, токены (`--accent:#F97316` и т.д.).

**ИИ-чат:**

2. **Этап 1 (закалка): ЗАВЕРШЁН (2026-06-11, сессия 3).** magic-bytes + санитизация имени (`app/services/uploads.py`); **CSRF** double-submit cookie (`app/services/csrf.py`, middleware в `main.py`, скрытое поле во всех формах, `verify_csrf` на всех POST); **rate-limit** (`app/services/ratelimit.py` — `/login` 10/5мин по IP+email, `/uploads` 30/5мин по user; План B=1 процесс, прод→Redis); **secure-cookie** (`COOKIE_SECURE=1`); **Alembic** (`alembic/`, baseline `6a191809dd51`; `init_db` ветвится dev=`create_all` / прод=`alembic upgrade head` при `USE_ALEMBIC=1`).
3. **Больше правил:** 2.303 (толщина основной линии 0,5–1,4 мм) — **ГОТОВО (2026-06-11)**, `check_lines_2303` по явным lineweight (молчит, если толщины не заданы). ## 10. Грабли и уроки (НЕ повторять)

1. **Starlette новая сигнатура шаблонов:** `templates.TemplateResponse(request, "name.html", {ctx})` — request **первым**. Старая `("name", {"request":...})` падает с `TypeError: unhashable type: 'dict'`.
2. **Консоль Windows = cp1251:** в скриптах `sys.stdout.reconfigure(encoding="utf-8")`, запуск с `$env:PYTHONUTF8='1'`. Иначе падение на «×» и мусор вместо кириллицы.
3. **bcrypt напрямую**, пароль усекать до 72 байт (passlib не дружит с bcrypt 4/5).
4. **Не удаляй `normacad.db`, пока сервер запущен** (Windows держит файл) — сначала `taskkill /f /im python.exe`.
5. **Glob по пути с кириллицей** (`БАЗА`) не сработал — используй прямой `Read`/grep по известным путям.
6. **Детект формата листа** — РЕШЕНО (2026-06-11): берём наибольший замкнутый контур (рамку-полилинию), а не общий bbox; `clean_a3` теперь даёт точные 420×297, текст за рамкой габарит не раздувает (`_largest_rectangle_mm` + тест `test_frame_not_inflated_by_outside_text`). Нет полилинии-рамки → fallback на bbox с предупреждением. Штамп распознаётся и по содержимому (графам наимен./обозн./масштаб), не только по имени блока — меньше ложного «нет штампа» на чужих DXF (`_has_title_graphs`).
7. **Числа только из детерминированного парсера**, не из LLM. **Тексты ГОСТ не сливать целиком** в облако.
8. Не использовать JWT (только серверные сессии). Не подключать сторонние CSS-фреймворки. Без эмодзи в интерфейсе.
9. **Реальные DXF ≠ синтетика (калибровка 2026-06-11, КОМПАС-экспорт).** Три ловушки, две давали ЛОЖНЫЕ замечания: (а) **текст и рамка лежат ВНУТРИ блоков** (INSERT) — парсер видел 0 текстов; нужен рекурсивный обход (`_iter_all` через `virtual_entities`, MTEXT → `plain_text`). (б) **рамка — не полилиния**, общий bbox раздувается → ложное 2.301; брать габарит из кандидатов ($EXTMIN/$EXTMAX, точный bbox, полилиния) и «прилипать» к стандартному формату. (в) **штамп без ATTRIB** → ложный critical «нет штампа»; детект по подписям граф ГОСТ в правом-нижнем углу, при этом значения граф не читать (`values_reliable=False`, заполненность → ручная проверка). Регресс закреплён фикстурой `build_realistic_clean`. Один файл — НЕ корпус: паттерны КОМПАС закрыты, другие CAD могут отличаться.
